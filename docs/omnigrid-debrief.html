What is the engine?

Think of it as the grid’s nervous system

Right now, keeping 100+ repos in sync is a manual job. Someone has to notice a branch is behind, open a PR, wait for review, merge it. The Omnigrid Automation Engine does that automatically — every 9 seconds it checks the pulse of the network, finds branches that have drifted, and brings them back in line.

It also handles the paperwork: approving Copilot’s clean code suggestions, merging low-risk content updates, flagging anything that needs a human eye. The goal is that you only get interrupted for decisions that actually need you — not routine housekeeping.

Currently, the engine’s main guardrail (ENGINE_ENABLED) is set to false. Every workflow checks this flag first. Nothing runs. This debrief is the step before flipping it.

The 4-layer safety architecture

1 Allowlist Gate
Only named repos can be auto-merged
The master config holds an explicit list of repos the engine may touch. Any repo not on the list is invisible to the automation — it can’t be merged, synced, or modified.
ONE_GRID_TIEKIEBOKS.json → repo allowlist
2 Branch Pattern Gate
Auto-merge only on claude/* branches
Even within an allowed repo, the engine only acts on branches matching claude/*. A Copilot PR targeting main directly stays in your hands, not the engine’s.
branch: "claude/*" → eligible · "main" → human only
3 Repo-Type Gate
Content repos auto, core infra needs you
The 33 Seedwave content sites are low-risk. Core infrastructure (banimal, sentinel, vaultmesh, claimroot) requires human approval before anything merges.
seedwave.faa.zone/* → AUTO · banimal|sentinel|vaultmesh → HUMAN
4 CI Gate
Each repo’s own tests are the final word
Even if layers 1–3 approve, the PR must pass all CI checks before merge. The engine never merges a red build. Last line of defence.
conclusion: "success" required · failure → held for review

What we are NOT changing

  • ENGINE_ENABLED stays false until you set it to true in GitHub → Settings → Actions → Variables.
  • No repo’s main branch is touched directly — only PRs on claude/* branches get auto-merged.
  • banimal, sentinel, vaultmesh, claimroot require your manual approval on every PR, regardless of branch name.
  • The allowlist in ONE_GRID_TIEKIEBOKS.json is not changed without your sign-off.
  • All 20 workflows continue checking ENGINE_ENABLED first — one toggle pauses the entire grid instantly.

What happens after you flip the switch?

You set ENGINE_ENABLED=true in GitHub Settings → Actions Variables. The next scheduled run (top of the hour) is the first live pulse.
